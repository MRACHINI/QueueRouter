Models & aliases

An alias is a stable model name for your apps (e.g. smart, code). QueueRouter rewrites it to the real model before forwarding, so you can switch models here without touching any app. Aliases show up in /v1/models with their target's context size. An alias's model or fallbacks can be other aliases: the request is forwarded to them, and each handles it its own way (council, answer check, fallbacks…).

Model names

Give a model on a provider your own name. It shows everywhere as Provider|your name (in opencode your name|Provider), and the model's automatic score, price and thinking levels are looked up by it. It's also the ID apps know the model by, with spaces as dashes (DeepSeek V4 Flash → DeepSeek-V4-Flash), and /v1/models shows QueueRouter's own entry for it, not the provider's. When more than one provider offers a model by the same ID, each one's ID ends in @Provider and apps must pick one: the bare ID is refused. The real ID is still what's sent to the provider, and apps may still send it. Empty the field and Save to go back to the ID.

Context sizes

How many tokens each model accepts. QueueRouter checks requests against it before queuing, and opencode is told it (so it compacts in time). It comes from the provider's model list; when a provider doesn't say, QueueRouter learns it from the provider's own "too long" error. Set it here by hand to fill a gap or correct a wrong value: on a row for that provider only, in this form for every provider that offers the model (a row's own value wins; a plan's context cap still applies on top).

Output is the longest answer: opencode is told it, and a bigger answer size an app asks for (Claude Code asks 128,000 for Opus) is lowered to it before sending. It comes from, first known first: yours, learned (the provider refused a bigger answer size and said its limit; the request was sent again at once), its list, models.dev (that provider's own figure when models.dev lists it, else the model maker's, else the median of the providers selling it); else default, 16,384 or half the context.

Thinking levels

Levels opencode offers next to a model (low / medium / high…), so you can choose how much it thinks before answering. They come from the upstream's own model list (OpenRouter states them), else from OpenRouter's public list by name. QueueRouter asks each upstream its own way: OpenRouter reasoning.effort, self-hosted vLLM servers the chat template's thinking switch (and low/medium/high), OpenAI-style APIs reasoning_effort. None are offered for ArliAI (its models think whatever is sent; tested) or Claude (each model thinks as it does by default). Set your own list to correct a model (e.g. none, low, high), or - for no selector; blank goes back to what's detected. opencode shows them through the QueueRouter plugin (opencode 2.x; re-install the plugin once to get this).

Lists the models your upstreams offer, plus names used in the last 30 days and manual prices. Empty override = automatic. Manual prices win over a reference; Remove price goes back to automatic. Costs are counted for the model that answered on the provider that served it (an alias's target), so price the target, not the alias. Prices apply to past usage too.

The price in opencode names is per million tokens of your mix: {{ "%.1f" | format(mix[0] * 100) }}% input, {{ "%.1f" | format(mix[1] * 100) }}% cached and {{ "%.1f" | format(mix[2] * 100) }}% output ({% if typical_mix %}a typical mix until there's more usage{% if mix_counts_since %} since {{ mix_since }}{% endif %}{% elif mix_counts_since %}your usage since {{ mix_since }}{% else %}your last {{ mix_days }} days{% endif %}). A monthly plan shows plan unless its row has a price of its own. Settings → opencode turns it off.

Usage before that day is left out of the mix, for days that don't look like how you use models now (a provider that didn't cache, a one-off job). Blank = the last {{ mix_days }} days; once the day is more than {{ mix_days }} days back it changes nothing. Nothing is deleted, and the Usage page stays as it is.
